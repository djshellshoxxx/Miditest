# MIDItest Native / CLAP / Linux / macOS Specification

Date: 2026-10-06
Status: implementation contract

## Targets

MIDItest ships from one native C++ codebase as:

- macOS Standalone application
- Linux Standalone application
- macOS CLAP plug-in
- Linux CLAP plug-in

The browser edition remains a separate Web MIDI front end.

## Runtime model

The native processor is a MIDI effect/utility. Incoming MIDI is passed through unchanged. Diagnostics are fed from a bounded real-time-safe queue into a non-real-time analysis model.

The audio/process callback must not:
- allocate diagnostic containers,
- run report serialization,
- update GUI components,
- write files,
- block on a mutex used by analysis,
- perform device enumeration.

If the input or output queue fills, an explicit dropped-event counter is incremented.

## Standalone behavior

Standalone mode is for physical/virtual MIDI-device diagnostics. JUCE Standalone provides Audio/MIDI settings through its Options menu. The selected MIDI input feeds the processor; MIDI generated by Output tools is routed through the configured standalone MIDI output.

Supported standalone workflows:
- raw/decoded monitor
- key/note inventory and held-note state
- duplicate Note On / unmatched Note Off detection
- CC range/coverage/unique/repeated/jump/reversal statistics
- pitch-bend range/center statistics
- clock BPM and event-rate statistics
- controlled Note/CC/Program/Pitch output
- all-channel panic
- report JSON export
- capture CSV export
- high-rate stress/overflow visibility

Physical disconnect/reconnect behavior is owned by the JUCE device layer; diagnostic queue drops are reported separately.

## CLAP behavior

The CLAP version diagnoses the event stream provided by its host and passes input events through. It must not claim direct physical-port visibility when the host does not provide it.

CLAP output-test messages are emitted to the host event output.

CLAP ID:
`com.circuitdriftlabs.miditest`

The CLAP is generated with `free-audio/clap-juce-extensions`, pinned to commit:
`55525c9858d4b25687be7759a5e0f70eccef218e`

Validation gate:
`clap-validator validate <MIDItest.clap>`

## GUI

The native editor follows the browser information architecture:

1. Quick Test
2. Monitor
3. Controls
4. Keyboard
5. Timing
6. Output
7. Mapping
8. Report

The layout is responsive/resizable. Raw protocol data uses monospaced text. Diagnostic summaries are text-first and do not rely on color.

Output controls are visible only in Output view. Report/capture exports are always accessible.

## Safety and robustness

- diagnostic history bounded to 5,000 events
- input bridge queue bounded to 16,384 events
- output queue bounded to 1,024 events
- SysEx copies at most 256 bytes into the real-time queue while retaining original byte length
- malformed data indexes above MIDI's 0-127 range cannot index fixed arrays
- Release tests remain active; they do not depend on `assert()`
- corrupt/short messages remain reportable without crashing

## Stress expectations

The million-event native stress test must demonstrate:
- exact total event accounting
- bounded 5,000-event history
- all 128 CC numbers detected
- high-rate measurement remains finite
- report serialization succeeds after stress

No claim of zero event loss is made above the bounded bridge capacity. Overflow must be visible to the user rather than blocking the real-time processing thread.

MIDItest Help
Getting started
Use a Chromium-based browser on a secure page. Enable MIDI, choose an input, then use Quick Test or Monitor.
SysEx
System Exclusive access is requested separately because browsers require an additional permission. MIDItest only displays observed bytes and does not interpret proprietary payloads.
Guided test steps
  1. Connection — enable MIDI and pick the input.
  2. Key sweep — press every key or pad once. Set an expected range on the Keyboard tab to list unseen keys.
  3. Velocity — play soft to hard, then strike one key repeatedly at similar force.
  4. Controls — move every knob/slider end to end, then leave it still for a moment.
  5. Pitch bend — push fully both ways and let it spring back several times.
  6. Mod / expression — sweep the mod wheel and expression controls.
  7. Buttons — press each button once.
  8. Pedals — press sustain and move expression pedals.
  9. Aftertouch — press into held keys if supported.
  10. Timing / loopback — optional, see below.
  11. Review — read findings, label mappings, save a baseline, export.
Skip marks a step as untested rather than failed. End stops the guided run and keeps the data.
What the measurements mean
Range / coverage: lowest and highest values seen, as a percentage of 0–127. Jitter: average size of back-and-forth value flicker while a control is moved little or not at all; a smooth sweep shows zero. Jumps: steps larger than 12 between consecutive values. Reversals: direction changes. Dead zones: gaps of 4+ values never reported. Bounce: a switch flipping back within 40 ms. These are measured observations and evidence for troubleshooting, not automatic hardware-failure diagnoses.
Advanced tests
The Tests tab runs ten analyses on the live capture (protocol audit, link health, double-trigger, velocity response, rollover, sweep linearity, encoder integrity, pitch-bend return, pedal polarity and a loopback burst test). Each card shows how to run it and explains what its result means.
Windows logs
In the Windows desktop app the Windows Logs tab scans the Event Log, Device Manager, services and setupapi/crash logs for MIDI and USB errors, explains each one and re-scans automatically after tests. In a browser, copy the PowerShell scan, run it on the PC and import the saved JSON (or import a setupapi.dev.log / Report.wer file).
Loopback
Connect a MIDI cable from the selected output port to the selected input port (or use a virtual loopback port such as loopMIDI on Windows), then press Run loopback. MIDItest sends a known Note/CC/Program/Pitch Bend sequence and counts matched, altered, missing and extra messages.
Latency limits
Latency is browser-to-MIDI-loopback round-trip time. It includes browser scheduling, operating-system MIDI drivers and the interface, and is not the same as DAW or audio driver latency.
Privacy
Capture, mappings and reports stay in the browser. MIDItest contains no MIDI telemetry backend.
